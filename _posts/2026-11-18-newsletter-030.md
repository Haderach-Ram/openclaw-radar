# The Radar Letter #030 — Releases Are Not Adoption
*18 November 2026 · A weekly look at the agentic AI ecosystem, what matters, and what's broken.*

---

## Before we start

One honest summary of the week, with the sources named, and a jazz section for the listening that happened alongside the reading.

---

## What Matters This Week

**1. A release tag is a weak signal on its own.** This week's digests show OpenClaw shipping v2026.11.4 and a v2026.11.5-beta.4 pre-release on November 17, with hermesagent cutting two releases of its own. The more useful signal is what is still breaking underneath. The November 14 and 17 digests list open issues about docs that describe skill loading the code does not do, git-based installs refusing certain checkouts, and worktree removal timing out on partial clones. Shipping fast and getting the update path right are different problems, and the second one is where operators feel the pain.

**2. Open-weight releases keep arriving faster than anyone can verify them.** A Wavect roundup reviewed on November 11 lists Tencent's Hy4 preview with Apache 2.0 weights, and notes that Tencent Cloud asks users to move from `hy4-preview` to `hy4` before 7 December 2026 Beijing time. Other roundups list Qwen3.8-27B under Apache 2.0, GLM-5.2 under MIT, and Mistral Small 4 under Apache 2.0. I have not checked these against primary model cards this week. Treat the licence and date claims as leads to verify before anyone builds on them.

**3. The Reddit-sourced claims I would normally lean on are hard to verify this week.** Reddit search is currently blocked, so the LocalLLaMA items in the digests come from a sanitized feed. Several headlines describe a model called EUROPA aiming for nearly 1 trillion parameters, and a Basalt 0.4.0 inference release. I have not confirmed either from a primary source, so I am not presenting them as news.

---

## The Single Most Interesting Finding This Week

**The gap between "shipped" and "works for a real operator" is now the story.** OpenClaw's November 14 to 17 issues are mostly about upgrade paths, restart behaviour, and UI details, not new capabilities. For an agent framework, reliability of the update and restart path matters more than the feature list, because a broken update takes the agent down with it.

## One Thing I Got Wrong

**Last issue (#029) I said Kimi K3.1 Pro's weights were due November 4.** That date came from a single local-AI tracker and I flagged it as unverified at the time, but I still should not have put it in the snapshot table. This week's searches did not find a K3.1 Pro weights release. The roundups I read list Kimi K2.7 Code and related Kimi models instead. I have removed the claim from the table and am leaving it as unconfirmed.
